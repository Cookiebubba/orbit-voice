# Security

Orbit can type prompts into Claude Code, an agent that can edit files and run commands on your computer. That makes its security worth taking seriously. This page explains what Orbit protects, how, and how to report a problem.

## Reporting a vulnerability

Please **don't open a public issue**. Use GitHub's private vulnerability reporting: **Security → Report a vulnerability** on this repository. Include what you found, how to reproduce it, and the impact. Expect a first reply within a week. Fixes ship as a new release with a note in the [changelog](CHANGELOG.md).

## What Orbit protects

| Asset | Threat | Protection |
| --- | --- | --- |
| Your Claude Code session | Someone else gets a prompt typed into it | A prompt is only sent after **you** confirm it: your reply after Grok reads the draft back (spoken, or typed in Orbit's own text box) must be a clear "yes", at most a minute old. There is no on-screen Send button; the bridge ignores the old button messages. Each reply is timed from when *that* speech started, so a late transcript of an earlier "yes" can't approve a newer draft. A spoken "no", "wait" or "change it", silence, or text inside a transcript never counts. A draft read back before an app notification or a second-brain answer came in can't be sent: a "yes" then may be about that, so Grok drafts it again and reads it back. After a hang-up nothing carries over: the next call starts with no draft, and a draft or "yes" from an earlier call is at most text in Orbit's resume note, which never counts as anything you said. The send re-checks that the same Claude session is still open. A draft for a brand-new session (started by voice) is only sent while that new, still-empty session is open, in the same project folder it was read back with. |
| Your Claude window | Something other than you moves it to another session | Grok can start a new session or switch sessions only right after **you** asked for it in your own words: never because of an app notification, text in a transcript or a second-brain answer. Your words count for 2 minutes when they ask for it themselves ("switch to…", "open…", a new session), even if a notification arrives before Grok acts. Each request switches or starts one session, and "don't switch" never counts. Any other words, like "yes" to Grok's offer, count only if said after the latest notification. A new session needs words like "new", "fresh" or "start over". With several Claude windows, Orbit acts in the one you were in last. A prompt goes only into the one window showing the session it was drafted for, never a guess between two. Switching may bring another Claude window to the front: that's the only focus change Orbit makes. Orbit presses only Claude's own controls: every UI Automation lookup is limited to Claude's own page, never a web page shown in its window (the Browser pane, previews), and the New buttons must sit directly in Claude's sidebar. A project name that matches more than one folder is refused rather than guessed. |
| Your Claude Code session | Text in a transcript or web page steers Grok (prompt injection) | Transcript content reaches Grok only as tool output marked as untrusted data, never as something you said. Orbit's own items (`[App notification]`, `[Orbit resume note]`, `[Orbit held answer]`) are labelled, and every quote mark and bracket in the text inside them is replaced, so nothing can pose as one of them. Each one resets the gates: drafting, switching, new sessions, copying and the second brain need your own words after it, unless your words already asked for exactly that (a request made just before a notification arrived still counts, once). The bridge also holds a notification back while Grok is still acting on what you asked. A second brain's `suggested_prompt` is only offered: it's drafted only after you ask for it, and sent only after the read-back and a fresh yes. The consent rule above is enforced by Orbit's code, not by asking the model nicely. |
| The local bridge (127.0.0.1:4317) | Another program, Windows user or web page drives it | A random per-launch token is exchanged once for an `HttpOnly; SameSite=Strict` cookie that only Orbit's own windows receive. Every API call and the voice socket require it. Host checks (DNS rebinding), Origin checks and `Sec-Fetch-Site` checks (CSRF) add defence in depth. |
| Your xAI key | Theft from disk or logs | Encrypted with Windows DPAPI (Electron `safeStorage`) in `%APPDATA%\Orbit\xai-key.bin`. Never written to logs (scrubbed) or sent anywhere but `api.x.ai`. |
| Your clipboard | Secrets leaking, or a planted command | Sending prompts never touches the clipboard: Orbit fills Claude's prompt box through Windows accessibility and presses Claude's own Send button. Grok can copy to the clipboard only when you asked to copy something in the last 2 minutes. Each request allows one copy, and "don't copy" doesn't count. Text Grok picks can't be copied on a request made before a second-brain answer, a held answer or the resume note came in. The exact draft or Claude's last reply can. What was copied is shown on screen, so nothing lands on the clipboard unseen. |
| Your project and machine | The second brain (Claude, asked by Grok) being steered into running or changing something, or leaking secrets | It runs your Claude Code headless in restricted mode with only read-only tools (Read, Glob, Grep), or none at all. There's no Bash, no edits and no web tools, and the file tools can't leave the project folder. It only explores the project of the session open in Claude, never your whole home folder or a drive. Each question needs new words from you since the last one (so it can't be looped), with at most 10 per conversation. A stopped or timed-out run is ended with everything it started, also when Orbit quits. It loads none of your Claude Code settings, hooks, plugins or MCP servers, so no inherited "bypass permissions" and no connectors. Common secret files inside the project (`.env*`, `.envrc`, `.dev.vars`, private keys, `.git-credentials`, `.ssh`, `.aws` and similar folders, `.git/config`) are denied. The question goes in on stdin, never on a command line, and nothing is saved to your session history. Orbit only ever runs a file named `claude.exe` on Windows (`claude` elsewhere), and a custom path must be a local absolute path, not a network share. Its answer reaches Grok as tool output marked as data, never as your consent. Its structured fields are checked and clamped, and unknown fields are dropped. If you hang up while it works (with "Grok tells me" and "Wake Grok when something you asked for is ready" on), the run carries on to its usual time and spending limit, and its answer is passed on later. Only one run goes at a time across calls. It stops if either setting or the second brain is turned off, and when Orbit quits. Signing Claude Code in again is Claude Code's own `claude auth login`, run with fixed arguments and no shell in a window of its own; Orbit never sees the credentials. It opens only from the Settings **Sign in** button, or when a second-brain run reported a sign-in problem, Grok offered, and your own reply afterwards was a yes. The status check (`claude auth status`) makes no model call. |
| Your Anthropic API key (optional) | Theft from disk or logs | Encrypted with Windows DPAPI in `%APPDATA%\Orbit\anthropic-key.bin`, used only by the second brain, never logged. By default the second brain uses your Claude Code sign-in and needs no key. |
| Your microphone | Always-on listening | Off by default. The "Hey Grok" wake word, when you turn it on, runs fully offline (Vosk) and only while Grok is off or asleep. Its audio never leaves the PC. It runs in a hidden helper page with its own script policy (the recognizer needs `eval` and WebAssembly), kept separate from the main window, which keeps the strict policy. "Wake Grok to say it" (spoken updates, off by default) connects only when Claude finishes. The page doesn't open the microphone until Grok's update has finished playing. The bridge itself drops all mic audio until then, forwards it for about 3 seconds (plus 1.5 s for speech that began inside the window to be detected), and hangs up if you didn't speak. Only speech that's transcribed into words continues the conversation (a cough or background noise doesn't), and that conversation hangs up after 20 s of quiet, and after 3 minutes at most unless you type to it. The hotkey or a click on the orb hangs up a wake at once. "Wake Grok when something you asked for is ready" (on by default) wakes the same way, only for a prompt you sent or a question you asked. The bridge decides every wake: at least 30 s apart, at most 6 an hour, and a session that just woke Grok can't wake it again for 3 minutes. Each wake bills a few seconds of xAI time. |
| Your machine | A tampered or broken update | Updates come only from this repository's published GitHub Releases, over HTTPS. The release build runs every npm package with read-only repository access and no stored credentials; a separate job that runs no npm code creates the release. Its actions are pinned to commit SHAs. Each download must match the SHA-512 in the release's `latest.yml` before it's installed, and a damaged download is thrown away. The installer isn't code-signed yet, so there's no publisher signature check: an update is as trustworthy as the GitHub account that publishes it. "Update automatically" can be turned off in Settings → Updates. |
| Your machine | Code execution through the app | Renderers are sandboxed with context isolation and no Node integration, on a supported Electron with security fuses set (no `ELECTRON_RUN_AS_NODE`, `NODE_OPTIONS` or `--inspect`, app code only from its integrity-checked archive). Navigation, IPC and permissions are locked to the local page by an exact origin match and external links open in your browser. The only permissions are microphone and notifications, for Orbit's own page. A strict Content-Security-Policy applies. PowerShell is called by full path with fixed arguments, and text is passed base64-encoded, never interpolated into a command. |

## What Orbit does *not* protect against

- **Malware already running as your Windows user.** It can read your files and control your desktop anyway.
- **What Claude Code does with a prompt you approved.** That's governed by Claude Code's own permission mode.
- **Data you choose to send to xAI.** The parts of your sessions Grok reads go to xAI to produce answers.

## Data handling

- **Stays local:** session transcripts are read from disk, read-only. Settings, usage and logs live in `%APPDATA%\Orbit`. Logs contain no keys and no prompt or transcript text. A call's end is logged with counts and codes only, such as seconds of audio and why the page hung up.
- **Kept in memory only, for 30 minutes:** the resume note (the last ~1,500 characters said in recent calls, the session that was open, a draft that wasn't sent), the prompts you're waiting on, and second-brain answers not passed on yet. None of it is ever written to disk or logs. It's dropped when it expires, when Orbit quits, and when the xAI key changes.
- **Sent to xAI:** your voice audio, whatever session text Grok reads to answer you, and the second brain's answers. With spoken updates on, also the title of each session Claude finishes in, and what Grok reads of that session to describe it. Within 30 minutes of a call, the next call also gets the resume note. That's text xAI already had, sent again, at most a few kilobytes.
- **Sent to Anthropic (second brain only):** the question Grok asks, the recent messages of your open Claude session, and any project files Claude reads to answer. It goes through your own Claude Code. Logs record only the model, the time taken and the cost, never the question or the answer.
- **No telemetry or analytics.** The only automatic request is the update check against GitHub Releases (at launch and every 6 hours), which you can turn off.

## Reviews

- **2026-10-20:** a review of resume notes, waking on results, structured second-brain answers and fixes to spoken updates found 15 issues (6 medium, 9 low), plus the root cause of silent wakes and 6 more bugs found by testing. No path to sending without your consent was found. All fixed except two accepted by design (the resume note has no switch of its own; waking on results is on by default). [Report and resolutions](docs/security/2026-10-20-review.md).
- **2026-10-19 (b):** a review of starting new sessions by voice, spoken updates while asleep and reading back a new session found 11 issues (2 medium, one of them older, and 9 low), plus 6 bugs found by testing. No path to sending without your consent was found. All fixed except one split-view limitation, documented below. [Report and resolutions](docs/security/2026-10-19b-review.md).
- **2026-10-19:** a review of everything since (second brain, stick-to-Claude helper, updater, release CI) found 13 distinct issues (3 medium, 10 low), plus robustness bugs found by a new fuzzer (`npm run fuzz`). All fixed except one browser-mode limitation, documented below. [Report and resolutions](docs/security/2026-10-19-review.md).
- **2026-10-18:** a full-repository review of 48 files at medium effort found 7 issues: 1 medium and 6 low. All were fixed before 1.0.0. [Report and resolutions](docs/security/2026-10-18-review.md).

## Known limitations

- The Windows installer is not code-signed yet, so SmartScreen will warn. Verify downloads against the `.sha256` file published with each release.
- Releases are built by GitHub Actions from the tagged source (see `.github/workflows/release.yml`).
- **Split view in Claude:** with two sessions side by side, Orbit reads the session title from Claude's page but types into the prompt box that has focus. Every send still re-checks that title, but use a single pane when sending by voice.
- **The resume note has no switch of its own.** It's memory only, kept 30 minutes and dropped when Orbit quits. Quit Orbit to forget recent calls straight away.
- **Developer test switches.** `ORBIT_FAKE_DESKTOP` (a stand-in for the Claude window, used by `npm run fuzz:e2e`) and `GVB_FAKE_MIC` / `GVB_SNAPSHOT_DIR` are honoured only when the app isn't packaged (`!app.isPackaged`), so the installed app ignores them. `ORBIT_DRY_RUN_SENDS=1` only makes sends safer (fill and clear, never press Send). A copy run from source trusts its environment like any developer tool.
- **Browser mode** (`npm run web`, for development) keeps the session in a cookie, and browsers send cookies to every port on 127.0.0.1. Opening a page served by another local program on another port could hand it the session. The desktop app is not affected: its windows never leave Orbit's own page.
