# Security review, 2026-10-19

A review of Orbit after 1.1.0: the second brain, Stick to Claude Code, the GitHub Releases updater and the release workflow, plus a re-check of the earlier findings. It found 13 distinct issues: 3 MEDIUM and 10 LOW, with no CRITICAL or HIGH. The fixes are below. A new fuzzer (`npm run fuzz`) found further robustness bugs, listed at the end. None of the 2026-10-18 findings (F1–F7) had regressed.

## Method

Three reviewers each read one surface of the whole repository, with extra attention to code added since the last review (`bf19784..1f5de73`):

- **Bridge:** `src/server.js`, `tools.js`, `sessions.js`, `config.js`, `watcher.js`, `log.js`, `clipboard.js`.
- **Electron shell:** `electron/*`, `src/desktop.*`, the build config and `.github/workflows/release.yml`.
- **Second brain and UI:** `src/brain.js`, the `ask_second_brain` path, secret storage, and `ui/src`.

Each candidate finding was traced through the exact code path. Claims about Claude Code's behaviour were checked against the installed CLI (2.1.303). Unsubstantiated candidates were dropped.

Fixes were verified in four ways:
- **Unit tests:** `test/security.test.js` and `test/sandboxed/tools.test.js`.
- **Differential check:** the new transcript parser gave identical results to the old one on all 350 local transcripts and all 121 sessions.
- **Live run:** a real `claude -p` second-brain run through the bridge with canary files. It couldn't read a file outside the project or a `.env` inside it.
- **Fuzzing:** repeated runs until clean.

## Findings and fixes

### M1. Release CI exposed a `contents: write` token to every build dependency (MEDIUM)
**What:** the single release job had write access, and `actions/checkout` left the token in `.git/config` while `npm ci` and `npm run dist` ran every package's scripts.
**Why it matters:** the app is unsigned, so the updater trusts whatever `latest.yml` and installer a release holds. One compromised dependency could have swapped the assets of a published release, and every installed copy would run them.
**Fixed:**
- The build job now has `contents: read` and `persist-credentials: false`.
- A separate `draft-release` job, which runs no npm code, downloads the build artifact and creates the draft.
- Code signing with a pinned `publisherName` is still recommended.

### M2. Second-brain "explore" could read outside the project, and the secret denylist was thin (MEDIUM)
**What:**
- Without `--restricted`, Claude Code's file tools aren't confined to the working directory.
- The deny rules missed `.git-credentials`, `~/.claude/.credentials.json`, `id_ecdsa`, `.dev.vars` and others.
- Grok could pick any session's folder by naming that session.

**Fixed:**
- `--restricted` added to every run. It was verified live: an outside file is refused.
- Deny rules widened, with upper-case variants, `.ssh`/`.aws`/`.azure`/`.kube`/`.gnupg`/`.docker` folders and `.git/config`.
- Explore reads only the project of the session open in Claude, never a home folder or drive root.
- A short "Claude is reading <project>…" note shows in the conversation.

### M3. A second-brain answer could put arbitrary text on the clipboard unseen (MEDIUM)
**What:** one utterance containing "copy", "clipboard" or "paste" authorized any `copy_to_clipboard(what:"text")` for 2 minutes, including text taken from an injected answer. The UI showed only a character count.
**Fixed:**
- A copy request is single-use.
- Negated phrasing ("don't copy") is refused.
- A request made before the latest second-brain answer can't be used after it.
- The copied text (up to 300 characters) is shown on screen.

### L1. A "yes" spoken before a draft could approve it (LOW)
**What:** transcripts were stamped with the latest speech start, not their own.
**Fixed:**
- Each transcript is stamped by its `item_id`'s speech start.
- A consent utterance must be at most 60 s old.

### L2. Quadratic regexes in transcript parsing (LOW)
**What:** `stripNoise` used lazy `[\s\S]*?` patterns. 300 KB of unclosed tags took about 2 s, repeated by the watcher.
**Fixed:** replaced by a linear `indexOf` scan with the same output. The same 300 KB-plus input now parses in milliseconds.

### L3. No limit on how often or how much the second brain runs (LOW)
**What:** Grok could chain questions with no user speech in between, up to $5 per Opus run. Runs also outlived Orbit, and `child.kill()` left ripgrep children running.
**Fixed:**
- Each question needs a new utterance since the last one.
- At most 10 questions per conversation.
- Abort, timeout and quit end the whole process tree (`taskkill /T /F`).
- The Settings connection test runs one at a time and stops if the page closes.

### L4. Tag name spliced into a pwsh script in CI (LOW)
**Fixed:** the tag is passed as an environment variable and validated against `^v\d+\.\d+\.\d+$`.

### L5. Origin checks used a prefix match (LOW)
**What:** `startsWith(baseUrl)` also accepted `127.0.0.1:43170` and `127.0.0.1:4317@elsewhere`.
**Fixed:** navigation, IPC sender and permission checks now compare the exact origin and reject credentials in URLs.

### L6. Electron 33 was out of support (LOW)
**Fixed:**
- Upgraded to Electron 44.5.1 with electron-builder 26.17.0.
- Fuses set: RunAsNode, `NODE_OPTIONS` and `--inspect` are off; embedded ASAR integrity and only-load-from-ASAR are on; cookie encryption is on.

### L7. Actions pinned by tag (LOW)
**Fixed:** all four actions are pinned to full commit SHAs.

### L8. `brainClaudePath` could point at a file Windows wouldn't actually run, or at a network share (LOW)
**Fixed:** on Windows only `claude.exe` is accepted. `\\` and `//` paths are rejected in settings and at run time.

### L9. Test script's fake server listened on all interfaces (LOW)
**Fixed:** `scripts/brain-e2e.mjs` binds to 127.0.0.1.

### L10. Browser mode: the session cookie reaches other ports on 127.0.0.1 (LOW)
**Status:** documented as a known limitation in SECURITY.md. It only affects `npm run web`, a development mode. The desktop app's windows never leave Orbit's own page.

### Hardening
The log scrubber now also hides Anthropic `sk-ant-` keys.

## Fuzzer findings

`test/fuzz/` runs the bridge in a sandbox:
- generated (often malformed) sessions and transcripts in a temporary home folder
- a fake Grok WebSocket server
- fakes for Claude's window and the `claude` binary, so it can never type into Claude or spend money

It drives random inputs through the settings sanitizer, consent check, log scrubber, session lookup, transcript parser, tool runner, HTTP API, static files and the voice socket. It checks these invariants:
- no crash, hang or 500
- no secret in any response
- no file served from outside `public/`
- `/api` requires the session cookie
- no prompt is ever sent without consent, and only text that was actually drafted

Bugs it found, all fixed:
- A session metadata file with a non-string `cwd`, `title` or `cliSessionId` broke the session list (`GET /api/sessions` returned 500, and every session tool failed). Fields are now type-checked, and the CLI id must be a plain id, which also keeps path fragments out of `findTranscript`.
- Transcript records with `null` parts, non-string `text` or non-array `content` threw.
- JSON values such as `{"toString": 1}` made the settings sanitizer throw ("Cannot convert object to primitive value"). Only plain values are converted now.
- The same kind of value as a draft id in `ui.send_draft`, `ui.edit_draft` or `ui.cancel_draft` caused an unhandled rejection.
- A WebSocket message over the 1 MB limit raised an uncaught `RangeError` in the main process (no `error` listener on the page socket).
- An upstream message that was valid JSON but had no string `type` threw in the async handler. Both socket handlers now contain and log failures.
- Tool names such as `constructor` or `toString` reached `Object.prototype` methods, and `null` arguments crashed a handler. Only a tool's own handlers run now, and arguments must be an object.
- `brainPrompt` trusted its inputs' types.
