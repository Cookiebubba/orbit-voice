# Claude Security results

Whole-repository scan of Orbit (`grok-voice-bridge`, branch `main`, commit `bf19784`) on 2026-10-18, at medium effort. The scan found 7 issues: 1 MEDIUM and 6 LOW, with no CRITICAL or HIGH. The main theme is that the local bridge on 127.0.0.1:4317 trusts any local process that sends the right Origin and Host headers. A second theme is that prompt consent is not bound tightly enough to the exact draft the user approved.

## Coverage

The inventory split the 48 tracked files into two components: **backend-server** (`src`, `electron`, `scripts`) and **ui-frontend** (`ui`, `assets`, `build`). Every top-level directory was accounted for, so the whole tree is covered. Two areas were skipped on purpose: `node_modules` and `ui/node_modules` ("third-party dependency trees, not first-party code"), and `dist` ("build output of packaged Electron app").

The run was sized at 48 tracked files, about 2 components of roughly 25 files each (at most 24 kept). One researcher per component covered each of three lenses: injection and input handling, authentication and authorization, and cryptography and secrets. A breadth sweep covered the files outside the components. All 7 researchers returned. The workflow decided from the language alone (JavaScript/TypeScript, which it took to be all managed code), before briefing any researcher, to give neither component a memory-safety lens. So no researcher in "backend-server" or "ui-frontend" was asked about memory-safety bugs.

Of the 40 tracked files inside the components, 31 were read to a conclusion and 9 sit under paths the researchers declared not reached. None are unaccounted for. The researchers' own account of what they did not read:

- **backend-server:** `ui/src` was only grepped (for `href`, `window.open` and `innerHTML`); `public/` (built output) was not read.
- **ui-frontend:** the vendored orbkit orb (`ui/src/components/ui/orbkit-core.tsx`, `shdr-29.tsx`) was only grepped. It is a WebGL visual whose only `dangerouslySetInnerHTML` injects a constant. The stylesheet, lockfile, `components.json`, `tsconfig` files and binary icons were not read, and `assets/icon.svg` was only grepped (no script or event handlers).

The panel finished in one verification run. No candidates were lost.

## Findings

### F1 — Voice WebSocket has no authentication: any local process that spoofs the Origin header can drive Grok and type prompts into Claude Code (MEDIUM, confidence medium)

**Impact.** Another account or a lower-privileged process on the same Windows machine can type prompts into your open Claude Code session as if you had sent them. It can also read your session transcripts through Grok and run up your xAI bill.

**Where.** `src/server.js:352` in `startServer`. CWE-306.

**What.** The `/voice` socket admits a client when its Origin and Host headers match `127.0.0.1:4317`. Browsers can't forge those headers, but any non-browser program can. Once connected, the client controls a Grok session that uses your key. Its `ui.send_draft` message reaches `sendToDesktop` without the spoken-confirmation check that applies to Grok's own `send_draft`.

**Exploit scenario.** A local process opens `ws://127.0.0.1:4317/voice` with `Origin: http://127.0.0.1:4317`. It sends `ui.text` asking Grok to draft a malicious prompt, then sends `ui.send_draft`. The bridge focuses your Claude window, pastes the text and presses Enter.

**Preconditions.**
- Attacker can run code as another local account or as a lower-integrity process on the same host.
- Orbit is running with an xAI key.
- For prompt injection, a Claude Code session with a visible prompt box.

**Fix.** Require a random per-launch secret that only Orbit's own windows receive. Check it on the socket handshake and on every `/api` request. Keep the Origin checks as CSRF defence, and bind `ui.send_draft` to a specific draft id.

**Verification.** 3/3 lens verifiers confirmed.

### F2 — HTTP API has no authentication beyond spoofable Origin and Sec-Fetch-Site headers (LOW, confidence high)

**Impact.** A local process can replace your stored xAI key, change settings, switch your Claude session, and read session titles, activity and logs.

**Where.** `src/server.js:225` in `startServer`. CWE-306.

**What.** POST endpoints are gated only by an Origin header the client picks. GET endpoints are gated only by the absence of a cross-site `Sec-Fetch-Site` header, which a non-browser client simply leaves out.

**Exploit scenario.** `curl -H 'Origin: http://127.0.0.1:4317' -d '{"key":"<attacker key>"}' http://127.0.0.1:4317/api/key` points your voice traffic at the attacker's xAI account. `GET /api/sessions` lists your sessions.

**Preconditions.**
- Attacker can run code as another local account or a lower-integrity process on the same host.
- Orbit is running.

**Fix.** The same per-launch token as F1, required on every `/api` request and compared in constant time.

**Verification.** 3/3 lens verifiers confirmed.

### F3 — Indirect prompt injection: Claude transcript text goes into Grok's context as a user message, and Grok's tools can type prompts into Claude Code (LOW, confidence medium)

**Impact.** Text an attacker gets into a Claude transcript can steer Grok into drafting and sending a prompt you didn't intend. Depending on Claude Code's permission mode, that prompt could edit files or run commands.

**Where.** `src/server.js:390` in the `/voice` handler's `announce`. CWE-1427.

**What.** When Claude finishes, its last message is inserted into a quoted sentence and sent to Grok as a user-role message. That text can come from a web page or file Claude read. `read_session` returns transcript text the same way. The only check before a voice send is that some speech started after the draft appeared, and any sound passes it.

**Exploit scenario.** Claude quotes attacker text that breaks out of the quotes and tells Grok to draft `run curl … | iex` and send it when the user next speaks. The user says "no, wait". That counts as speech, and the prompt is sent.

**Preconditions.**
- Announcements set to "speak", or the user asks Grok to read a session.
- Attacker-influenced text reaches Claude's output.
- Grok follows it despite its instructions.
- Any speech after the draft appears.
- An empty prompt box in the same session.

**Fix.** Pass transcript content to Grok only as delimited data, not as a user message. Require a confirmation the server checks itself before sending.

**Verification.** 3/3 lens verifiers confirmed. The panel lowered the severity from MEDIUM to LOW (confirming votes: MEDIUM, LOW, LOW).

### F4 — Malformed percent-encoding in a static-file URL throws an uncaught URIError in the async request handler (LOW, confidence medium)

**Impact.** One crafted request (`GET /%`) can crash the bridge in browser mode (`npm run web`). In the desktop app it raises an unhandled error. Nothing is disclosed.

**Where.** `src/server.js:333` in the request handler. CWE-248.

**What.** `decodeURIComponent` on the static-file path runs outside the handler's try/catch, so a lone `%` rejects the async listener.

**Exploit scenario.** Any web page includes `<img src="http://127.0.0.1:4317/%">`. In `npm run web` mode Node exits.

**Preconditions.**
- Bridge running.
- A browser or local process can reach `127.0.0.1:4317`.

**Fix.** Catch decoding errors and return 400, and make the whole listener reject-safe.

**Verification.** 3/3 lens verifiers confirmed.

### F5 — TOCTOU in doSend: the draft checked for consent can be replaced by a concurrent draft_prompt before it is sent (LOW, confidence medium)

**Impact.** A prompt you never saw or approved can be sent in place of the one you approved.

**Where.** `src/tools.js:148` in `doSend`. CWE-367.

**What.** `send_draft` checks consent against the current draft, then awaits a PowerShell probe of about a second. Only after that does it read the shared `draft` variable. Tool calls aren't serialized, so a concurrent `draft_prompt` can swap the text in that window.

**Exploit scenario.** A manipulated model emits `draft_prompt(B)` and `send_draft` in one response, right after the user approved A. B's draft lands during the probe, and B is sent.

**Preconditions.**
- The model issues both calls together, for example under prompt injection (not verified by execution).
- The user confirmed some earlier draft.

**Fix.** Snapshot the draft (id and text) at the consent check and send only that snapshot. Serialize tool calls per connection.

**Verification.** 3/3 lens verifiers confirmed.

### F6 — Clipboard restore re-writes a password-manager secret as plain text and drops its exclusion markers (LOW, confidence medium)

**Impact.** A password you had copied from a password manager can end up in Windows Clipboard History or the cloud clipboard, and may escape the manager's auto-clear.

**Where.** `src/desktop.ps1:202` in the send step. CWE-312.

**What.** The send step saves the clipboard as plain text, pastes the prompt, then writes the text back. That drops the "exclude from history and cloud" markers password managers set.

**Exploit scenario.** You copy a password in Bitwarden, then send a prompt through Orbit within the auto-clear window. With Clipboard History or Cloud Clipboard on, the password is now in Win+V history and synced.

**Preconditions.**
- Clipboard History or Cloud Clipboard turned on (both off by default).
- A password-manager secret on the clipboard at send time.
- Someone who can read that history or a synced device.

**Fix.** Don't route the prompt through the clipboard (UI Automation `SetValue` or simulated typing), or restore the full clipboard data object unchanged and mark Orbit's own paste as excluded.

**Verification.** 2/3 lens verifiers confirmed.

### F7 — Clicking Send approves whatever draft is current when the server acts, not the text and session the user saw (LOW, confidence medium)

**Impact.** Your Send click can be spent on a different prompt, or a different session, from the one on screen.

**Where.** `ui/src/useVoice.ts:359` in `sendDraft`. CWE-367.

**What.** The Send button sends only `{type:"ui.send_draft"}`, with no draft id. The server then reads whichever draft is current after its PowerShell probe, so a draft or session change by Grok in that window gets sent instead.

**Exploit scenario.** You click Send on draft A. During the 1–3 s probe, Grok (steered by transcript text) drafts B or switches session. B is pasted.

**Preconditions.**
- Attacker text reaches Grok and Grok follows it.
- The change lands within the probe window.
- The user clicks Send.

**Fix.** Send the draft's id with the click and refuse if it no longer matches. Pass the expected session title to the send script and check it right before pasting.

**Verification.** 2/3 lens verifiers confirmed.

## What was verified

Researchers read the code across three vulnerability lenses per component, plus a breadth sweep. Each candidate then went to a three-voter panel judging reachability, impact and defences, and a candidate needed 2 of 3 votes to stay. F1–F5 were confirmed unanimously and F6–F7 by 2 of 3. The renderer stamps the verification status from those votes. Every finding comes from reading the code: no tests were run and no exploit was executed.

---

## Resolution (Orbit 1.0.0)

Every finding above was fixed before the first public release. The fixes were checked with a scripted regression test against a running bridge (14 checks, all passing) and, for the spoken-consent check, against xAI's live transcription.

| # | Finding | Status | What changed |
| --- | --- | --- | --- |
| F1 | Voice socket had no authentication | **Fixed** | Every launch generates a random 256-bit token. Orbit's own windows trade it once (`/auth`) for an `HttpOnly; SameSite=Strict` session cookie, and the voice socket refuses any connection without it. Origin and Host checks remain as CSRF and DNS-rebinding defence. |
| F2 | HTTP API had no authentication | **Fixed** | The same session cookie is required on every `/api` call, compared in constant time. |
| F3 | Transcript text reached Grok as a user message; any sound counted as consent | **Fixed** | "Claude finished" notifications now carry only a sanitized session title. Grok fetches the details with `read_session`, so they arrive as tool output (data) labelled as untrusted. A voice send now requires the user's transcribed reply after the draft to be a clear yes, with no "no / wait / don't / change". |
| F4 | Malformed URL crashed the request handler | **Fixed** | Decoding errors return 400, and the whole request handler is wrapped so no rejection goes unhandled. |
| F5 | Draft could be swapped between consent and send | **Fixed** | The approved draft is snapshotted before any await and sent only if it is still the current draft. Tool calls on a connection now run one at a time. |
| F6 | Clipboard restore leaked password-manager secrets | **Fixed (removed)** | Orbit no longer uses the clipboard at all. It fills Claude's prompt box through UI Automation `ValuePattern.SetValue` and presses Claude's own Send button with `InvokePattern`, with no key presses, focus changes or clipboard writes. |
| F7 | Send button didn't name the draft it approved | **Fixed** | The button sends the draft id. The server refuses a mismatch, and the send step re-checks that the draft's session is still the one open in Claude right before filling the box. |
