# Security review, 2026-10-20

A review of three additions, and of fixes to the spoken update that failed in real use:
- **Resume notes:** the next call gets Orbit's own record of the last one.
- **Wake on results:** Grok wakes when something the user asked for is ready (a prompt sent to Claude, or a second-brain answer that came back after hanging up).
- **Second-brain answers built for voice:** structured output from Claude Code (`spoken`, `details`, `files`, `suggested_prompt`, `confidence`).
- **The spoken update ("Wake Grok to say it"):** in use, Grok woke but wasn't heard, the mic window sometimes never opened, and wakes came back to back.

It found 15 distinct issues: 6 MEDIUM and 9 LOW, with no CRITICAL or HIGH. No path was found that sends a prompt into Claude without the user's consent, or that makes text in a resume note, a held answer or a second-brain field count as the user's words. 13 are fixed; 2 are accepted and documented. Testing found the root cause of the silent wakes and 6 more real bugs, all fixed.

## Method

Three reviewers each read the whole change (commit `cfaa50a` on `1f3c3c7`) through one lens:

- **Consent and gating across reconnects:** resume notes, restored drafts, wake handoffs, held answers and `suggested_prompt`.
- **Privacy and memory:** what is kept, where and for how long, and what reaches logs, xAI or the event stream.
- **Wake abuse and cost:** loops, caps, spacing, a paid second-brain run that outlives its call, and quitting.

They read code only and ran nothing. Each finding was traced through the exact code before it was fixed or accepted.

Fixes were verified in four ways:
- **Unit tests:** `test/continuity.test.js` (new), `test/brain.test.js` (structured output, hand-over), and `test/sandboxed/wake.test.js` (new, 17 tests at the bridge against a fake Grok).
- **Fuzzing:** two new phases, `resume` and `wake`, plus malformed and hostile structured answers in the units phase. Each new phase has its own invariants. The fuzzer was run over seeds 1 to 10 until clean.
- **The real Orbit page in Electron** (`npm run e2e:wake`): a hidden window, like Orbit in orb mode, with a fake Grok that speaks a real 1.5 s tone. It runs on its own port and its own profile, so it never touches a running Orbit.
- **A live second-brain run** with Claude Code 2.1.303 (Haiku, under $0.003 in total) to confirm how structured output comes back.

## Root cause: Grok was silent on spoken updates

**What:** the page's play head (`playHead`, where the next audio chunk starts) outlived the call. When a call ended, it was left at that call's AudioContext time, which is about how long the call lasted. The next call makes a new AudioContext, whose clock starts at 0.

In an ordinary call you speak first, and that resets the play head. In a spoken update nobody speaks first. Grok's audio was therefore scheduled as many seconds into the future as the previous call had lasted. After a long conversation it never played at all. After a short one it played late, or was cut off by the hang-up. The captions still showed Grok's words.

**Evidence:** in Electron, a 7 s call, then a wake, without the fix: the page put Grok's first chunk **7.0 s ahead** of its clock, and the wake took 12 s instead of 5. With the fix it's **0.0 s ahead**, and all 1.5 s of audio played inside the wake. The Windows output path itself was fine, as was checked separately with the user's headset.

**Fixed:**
- The play head and the playback counters reset with every new AudioContext.
- A play head more than 2 minutes ahead of the clock is treated as stale and pulled back.
- "Still playing" is now judged by the wall-clock end of the queued audio, not by `ended` events. Audio that never comes out can no longer keep the mic shut or a hang-up waiting.
- At hang-up the page reports, in numbers only, how much Grok audio it scheduled and played and how far ahead the first chunk was. The bridge adds Grok audio received and the page's reason for hanging up to the end-of-call log line. For example: `Grok audio received 1.5s, page: listen_expired, page scheduled 1.5s, played 1.5s, first chunk 0.0s ahead`.

## Findings and fixes

### M1. A second-brain `suggested_prompt` could be drafted without the user asking (MEDIUM)
**What:** `draft_prompt` only needed the user to have spoken after the latest app notification, not after the latest second-brain answer. A project file read by the second brain could put up to 800 characters into `suggested_prompt`, and Grok could draft it on the user's question alone. The user would then hear "a prompt to fix the bug" and might say yes to hidden text.
**Fixed:** a draft needs the user's own transcribed words after the latest notification *and* the latest second-brain answer. The offer ("Want me to send Claude a prompt for that?") and its yes come first, then the draft, the read-back and a fresh yes. The wording is the same in the instructions, the tool result and held answers.

### M2. A "yes" could approve an older draft after something else came in (MEDIUM)
**What:** `send_draft` accepted any clear yes after the draft. If a notification or a held answer arrived between the read-back and the answer ("Want me to send a prompt for that?"), the user's yes to *that* could send the earlier draft.
**Fixed:** a draft made before the latest notification or second-brain answer isn't sendable. Grok must call `draft_prompt` again, read it back and get a fresh yes. The fuzzer checks this on every send.

### M3. The resume note has no switch of its own (MEDIUM, accepted)
**What:** turning off "Wake Grok when something you asked for is ready" clears awaited items and results, but not the note's transcripts.
**Status:** accepted. The user asked for no new UI beyond one toggle. The note is memory only, for 30 minutes. It's dropped when Orbit quits and when the xAI key changes, and is now swept on a timer. It's documented in SECURITY.md and the README.

### M4. A paid second-brain run was kept past hang-up where the setting isn't shown (MEDIUM)
**What:** keeping a run going needed only `wakeOnResults` and the second brain to be on. The toggle only shows with "Grok tells me", so with "Chime only" or "Off" a run could keep going (up to $5 and 5 minutes on Opus) with no visible way to stop it. The wake reviewer found this too.
**Fixed:** a run is kept only with "Grok tells me" and the toggle on, and never once the app is quitting. Switching either off stops a held run.

### M5. Waking on results is on by default (MEDIUM, accepted)
**What:** new installs wake Grok for results without opting in, unlike "Wake Grok to say it".
**Status:** accepted: the user asked for it on by default. It wakes only for things you asked for (a prompt you sent, a question you asked), at most 6 times an hour and at least 30 s after the last call. Each wake also has a hard end (M6).

### M6. A wake that became a conversation had no maximum length (MEDIUM)
**What:** once words were heard in the 3 s window, only the quiet timers ended the call. A TV in an empty room could keep a wake going, streaming room audio and billing xAI.
**Fixed:** a call Grok started by itself hangs up after 3 minutes (`WAKE_LIMITS.callMaxMs`) unless the user typed to it.

### L1. Lookalike quotes and brackets passed the text cleaners (LOW)
**What:** fullwidth `＂`, `〝〞`, `〖〗`, `⟦⟧` and similar could make a session title or answer field look like "[App notification]" to the model. The bridge's gates still held.
**Fixed:** `quoteSafe` maps every Unicode quote mark and bracket class (`\p{Pi}\p{Pf}\p{Ps}\p{Pe}` and the stragglers). `notifyTitle` now uses it.

### L2. A sound that never became words unlocked drafting (LOW, older than this change)
**Fixed:** with M1, drafting needs transcribed words. Orbit waits up to 4 s for a transcript that's still on its way.

### L3. The page's hang-up reason could grow without limit (LOW)
**Fixed:** it's set once per `ui.bye` from fixed codes and range-checked numbers. Anything else is dropped.

### L4. Expiry only happened when Orbit next looked (LOW)
**Fixed:** a timer sweeps expired notes and items every minute.

### L5. Awaited prompt text was stored at full length (LOW)
**Fixed:** it's stored at 300 characters, and questions at 300 too.

### L6. The per-session wake cooldown map could creep (LOW)
**Fixed:** entries past the cooldown are pruned at every wake, and the map is capped at 50.

### L7. Second-brain answers survived turning the second brain off (LOW)
**Fixed:** unspoken second-brain answers are dropped with it.

### L8. A run in a closing call could be handed over after quit's sweep (LOW)
**Fixed:** `stopBackgroundWork()` sets a quitting flag. After it, nothing is held, and a run handed over is stopped instead.

### L9. Two calls at once could each start a paid run (LOW)
**Fixed:** a bridge-wide count allows one second-brain run at a time, across held runs and calls that are on.

### Also fixed (informational)
- **Second-brain failure text in the log, older than this change.** Its fallback could quote the run's output. The log now keeps only Orbit's own sentence.
- **A new xAI key now drops the resume note,** so earlier transcripts don't go to another account.

## Found by testing

All of these are fixed.

- **The mic window never opened (wake test, the field report's "would not let me tell it to go to sleep").** The bridge only sent "ready" when the reply that finished had audio and no tool call. With a tool call, then a spoken reply, then a reply without audio, it never came: the mic stayed shut until the page gave up after 45 s. Now Grok is ready once it has spoken at any point since the wake and is idle. If it never made a sound, the window opens after 2 s anyway. The hotkey or a click on the orb hangs up a wake at once.
- **Two reply requests at once (wake test).** After a tool call, the bridge could ask Grok for a reply and pass on a queued notification with a second request in the same moment. Notifications now wait until Grok has started the reply already asked for, or 5 s.
- **Back-to-back wakes (field report: three in a minute, one 0.5 s after the last).** Wakes are now asked for by the bridge, never by the page on its own. One wake says everything that's due, and updates arriving during it join it. Wakes are at least 30 s apart and at most 6 an hour, and a session that just woke Grok can't wake it again for 3 minutes unless it's your result.
- **A new result could wait behind an old wake request (wake test).** After asking the page to wake, the bridge didn't ask again for 30 s, even for something new. Something newly due now asks at once, within the spacing and cap.
- **`read_session` could read the wrong session (review of the field report).** Two sessions can share a title, so updates now name the session by its id. A read works with the Claude window gone (minimized or in the tray).
- **The note builder threw on odd input (fuzzer).** It now takes only plain numbers and strings.
- **Spoken answers were cut at "src/a.js" and URLs swallowed full stops (unit test).** Sentences now end only at punctuation followed by a space.
- **Mistakes in the test tools, not in Orbit.** Running `npm run fuzz -- --seed N` from PowerShell dropped the arguments, so a random seed ran; the loop calls node directly. A test asked the second brain a two-character question, which the tool refuses. The Electron check awaited `app.whenReady()` at the top of an ES module, which hangs. A test helper waited 2 s for a tool that waits 4 s for a transcript.

## Structured output, as Claude Code returns it

`claude -p --output-format json --json-schema '<schema>'` returns the answer in the result's `structured_output` field. It also writes the same JSON as a string in `result` when the model wrote no text of its own. This was confirmed from the CLI's own strings (`SDKResultMessage.structured_output`, the `error_max_structured_output_retries` subtype) and a live Haiku run. A broken schema is refused at startup ("--json-schema is not a valid JSON Schema"). The schema works with `--tools ''` (think) and with Read, Glob and Grep (explore).

Orbit reads `structured_output`, then `result` as JSON, then plain `result` text. Every field is checked and clamped:
- `spoken`: three sentences and 400 characters, with code, markup and links removed
- `details`: 4000 characters
- `files`: at most 8 clean path references
- `suggested_prompt`: 800 characters, on one line
- `confidence`: high, medium or low

Unknown fields are dropped.
