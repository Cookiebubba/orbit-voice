# Orbit parity suite

One set of test cases that both Orbit builds must pass: the Electron app and Orbit Native (the
Swift app in `mac-swift/`). The cases are JSON data, the apps are driven through a small HTTP driver
each build serves in test mode, and two runners execute them: `run.mjs` (Node) and the
`OrbitParityTests` XCTest target (Swift). The protocol, the step kinds and the matchers are in
[PROTOCOL.md](PROTOCOL.md).

## Areas

| File | Area | What it checks |
| --- | --- | --- |
| `cases/bridge.json` | bridge | The bridge's HTTP/WebSocket contract as each app runs it: sign-in, host/origin/cross-site guards, config, settings, keys, voices, speech models, logs, static pages and their CSPs, the wake model, path traversal, the voice socket's guards, a call reaching (the stand-in) Grok. |
| `cases/settings-roundtrip.json` | settings | Every setting the Settings screen shows, both ways (app → bridge, bridge → app live), the hotkey, open at login, settings kept across a restart. Generated by `tools/gen-settings-cases.mjs` from `src/config.js`. |
| `cases/avatar.json` | avatar | Qubit on the stand-in Claude window: his strip, standing on the prompt box, following the window, click-through, click to talk, pick up and throw inside the window with "Wheee!", a gentle put-down without, sleep then click, one avatar per place while switching, free-floating, None, his art rules. |
| `cases/onboarding.json` | onboarding | The macOS permissions onboarding over faked permission states. |
| `cases/window.json` | window | Driving the stand-in Claude window: found, sessions, switch, drafts typed into its box, send on a yes, Stop, answering a card. |
| `cases/voice.json` | voice | Spoken scenarios end to end: a synthesised clip into each app's own microphone path, on-device speech to text, a scripted Claude Code, the tool calls and their effect: draft, a natural yes, a no, same-breath send, go to sleep, stop, answering a card, switching the model, an avatar command. |

## Running (on a Mac)

```bash
npm ci && npm run build:ui && node scripts/fetch-model.mjs   # once
npm run parity:audio                                       # once: speech models (~175 MB) and the clips
bash mac-swift/scripts/build-app.sh --test                 # the Swift build with its driver allowed
npm run parity -- --app both                               # or --app swift / electron, --area, --case
```

The matrix goes to `parity/out/matrix.json` and `parity/out/matrix.md`. The same cases from Swift:

```bash
cd mac-swift && swift test --filter OrbitParityTests        # ORBIT_PARITY_AREA=avatar, ORBIT_PARITY_APP=electron
```

## Test doubles (never the real thing)

- **Stand-in Claude window** (`fixtures/standin`): the macOS port's fake Claude page in a Chromium
  window, with a control port. Both apps act on its pid only (`ORBIT_TEST_CLAUDE_PID`).
- **Stand-in desktop driver** (`fixtures/fake-desktop.mjs`, from `test/e2e/fake-desktop.mjs`): for the
  voice scenarios, where what matters is the tool call, not the window.
- **Scripted Claude Code** (`fixtures/fake-claude.mjs`): `claude -p` stream-json with replies from the
  case's rules; Claude voice's speech is real.
- **Stand-in Grok** (`fixtures/fake-grok-server.mjs`, from `test/e2e/fake-grok.mjs`).
- Each case gets a fresh app with a throwaway profile, a fake xAI key where one is needed, muted
  output, a faked login item and faked permission states where a case says so.

Several areas need a macOS permission for the app under test (Accessibility for the window and
avatar areas). Without it those cases fail for that build, and the matrix shows it.
